# 部署手册

> 前端是**纯静态**：`npm run build` 出 `dist/`，丢给 nginx；接口全靠 `/api` 反代到后端，同域部署不用配 CORS。

---

## 一、本地开发

```bash
npm install
npm run dev        # http://localhost:5173，/api 代理到 http://localhost:8080
```

后端要同时起着（`D:\maven-project\aichat`）：

```bash
./mvnw.cmd -o spring-boot:run
# 需要 MCP notes 工具时：set SPRING_PROFILES_ACTIVE=local
```

登录：短信服务未配置时，本地可用密码登录；或用一次性脚本往 Redis 里种一个 token（见后端 `docs/本地启动.md`）。

---

## 二、构建

```bash
npm run build      # 产物 dist/（index.html + assets/）
npm test           # 41 个纯函数单测，改 utils/ 后必跑
```

`vite.config.js` 已做三件与生产相关的事：

- `manualChunks` 分包（vue / element-plus / markdown / axios），首屏不必等全部
- 生产固定同源 `/api`，`VITE_API_BASE_URL` 不参与生产 baseURL
- 开发代理对 SSE 请求去掉 `Accept-Encoding`、加 `Cache-Control: no-cache`

## 三、服务器部署（单机 nginx）

目录约定（服务器上）：

```
/opt/mindbutler/
├── dist/            # 前端静态文件（本文件上传）
├── app.jar          # 后端
└── logs/            # 后端日志
```

### 1. 上传前端

```bash
npm run build
scp -r dist/* root@<服务器IP>:/opt/mindbutler/dist/
```

### 2. nginx 配置

把仓库里 [`nginx/ai-chat.conf`](../nginx/ai-chat.conf) 复制到 `/etc/nginx/conf.d/ai-chat.conf`，改两处：

```nginx
server_name <服务器IP或域名>;         # 原来是 localhost
root /opt/mindbutler/dist;          # 原来是 Windows 路径
```

配置里三个 SSE 关键点别删：`proxy_buffering off`、`proxy_set_header Accept-Encoding identity`、`proxy_read_timeout 300s`——删了打字机效果会变成"憋一大段再吐"。

```bash
nginx -t && nginx -s reload
```

### 3. 后端

```bash
# 打包（本地）
./mvnw.cmd -o -DskipTests package
scp target/*.jar root@<服务器IP>:/opt/mindbutler/app.jar

# 服务器上跑（示例，生产建议挂 systemd）
java -jar /opt/mindbutler/app.jar \
  --spring.profiles.active=prod \
  --spring.datasource.url=jdbc:mysql://127.0.0.1:3306/aichat \
  --spring.data.redis.host=127.0.0.1
```

生产必须配的环境变量 / 参数：

| 键 | 说明 |
|---|---|
| `spring.datasource.url/username/password` | MySQL |
| `spring.data.redis.host/port/password` | Redis |
| `spring.ai.openai.api-key` | 用 DeepSeek 时必须配（`base-url=https://api.deepseek.com`） |
| `app.cors.allowed-origins` | 同域部署可留默认；前后端分域必须改成真实域名，否则浏览器直接拦 |
| `APP_CHAT_DAILY_LIMIT` | 每人每天对话次数上限，`0` 表示不限 |
| `app.mindbutler.task.zone` | 只允许 `Asia/Shanghai`，写错启动即失败（故意 fail-fast） |

### 4. 验证清单

1. `curl -I http://<IP>/` → 200，返回 `index.html`
2. `curl http://<IP>/api/chat/models` → 401（说明反代通了，只是没登录）
3. 浏览器登录 → 发一条消息 → **文字逐字出现**（SSE 生效）
4. 说"记住我喜欢简洁" → 弹确认弹窗 → 保存 → 刷新还在
5. 刷新任意子路由（如 `/settings`）→ 不 404（SPA fallback 生效）

## 四、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 消息一次性出现，没有打字机效果 | nginx 缓冲没关 | 检查 `proxy_buffering off` 是否在 `/api/` 里 |
| 401 循环跳登录 | nginx 没转发 `Authorization` | `proxy_set_header Authorization $http_authorization;`（一般默认转发，被别的配置覆盖时会丢） |
| 跨域报错 | 前后端不同域且后端 CORS 只放 localhost | 改 `app.cors.allowed-origins` 或改成同域反代 |
| 刷新子路由 404 | 缺 `try_files $uri $uri/ /index.html` | 补上 |
| 静态资源 404 | `root` 还是 Windows 路径 | 改成服务器上的 `dist` 绝对路径 |
